# Project context

This is the repository of the vial-sort project: a low-cost SO-101 arm moves small vials between two racks and a bin, following a command that names the slot to take the vial from and where to put it. Models are trained on recorded demonstrations and tested on the arm.

The repository holds the project's knowledge and its public face: these records, the generated data of every run, the operator's notes, the model descriptions, and the website that presents them at `https://cognitive-software-labs.github.io/vial-sort/`. The training, evaluation and robot code is not here yet. It lives in a separate checkout that the scripts expect at `~/lerobot`; [moving it here](topics/code-migration/code-migration.md) is open work.

## Repository map

- `src/pages/`: one file per page. `index.astro` (home), `datasets.astro` (Data), `training.astro`, `models.astro`, `method.astro` (Testing), `results.astro`, `glossary.astro`, `previous/` (the August work).
- `src/components/`, `src/layouts/`, `src/styles/global.css`, `src/charts/`, `src/lib/`: the site's parts, shared layout, styles, page scripts and helpers.
- `src/data/*.json`: generated by `scripts/build_data.py` and its siblings. Never edited by hand.
- `public/media/`, `public/img/`: generated videos, posters and images. Tracked, because the deploy does not regenerate them.
- `scripts/`: the data and media pipeline and the checks. The [capability map](CAPABILITY_MAP.md) lists each one.
- `notes/`: the operator's notes from arm tests (`.txt`, the source) and the yaml made from them.
- `models.yaml`, `curation.yaml`: model descriptions, and which recordings the pages show.
- `.docs-kit/`: the documentation kit, a Git submodule pinned to `v6.0.0`. Read it, never edit it here.
- `docs/`: these records. `docs/experiments/` holds the dated Lab notes; `docs/site/site.toml` configures the documentation site.
- `public/docs/`: redirects from the Lab notes' former addresses. Nothing else belongs there: the documentation is copied into `dist/docs/` at build time.
- `dist/`, `.astro/`, `.build/`, `node_modules/`: generated or installed, ignored by Git.

The documentation is published with the website, at `/vial-sort/docs/`. Until 2026-11-28 that address held the Lab notes as website pages; they are now records under `docs/experiments/`.

## Build and review

### The website

Needs Node.js 22.23.4 or later; the deploy uses Node 24.

```bash
npm install
npm run dev        # http://localhost:4321/vial-sort/
npm run build      # writes dist/
python3 scripts/check_text.py dist   # glued words and leaked private paths in the built pages
```

`scripts/check_text.py` has not been run on the Windows development machine; the deploy workflow does not run it either.

### Publishing

Every push to `main` builds the website and this documentation and publishes both to GitHub Pages (`.github/workflows/deploy.yml`). There is no staging site. A push is a publication, so it needs the person's go for that push. The documentation is linted strictly in that workflow; a lint error stops the publication.

### The site's data

`scripts/update_site.py` runs the whole path from the operator's notes to a rebuilt site. It needs Python, ffmpeg and the `~/lerobot` checkout with the recordings, so it runs on the workstation, not on the Windows development machine. The [website record](topics/website/website.md#where-the-numbers-come-from) has the steps.

### The documentation site

Needs Python 3.12. From the repository root:

```bash
python3.12 -m venv .build/docs-env
.build/docs-env/bin/python -m pip install -r .docs-kit/requirements.txt
.build/docs-env/bin/python .docs-kit/docsite.py build --project .
.build/docs-env/bin/python .docs-kit/docsite.py lint --project . --strict
```

On Windows the interpreter is `.build\docs-env\Scripts\python.exe`, and the environment variable `PYTHONUTF8=1` must be set first: without it the kit's build and lint stop with a `UnicodeDecodeError`, observed with kit 6.0.0 and Python 3.12.10 on 2026-11-28.

The output is `.build/docs/html/`.

### The combined site

To see the website and the documentation together as they are published, build both and copy the exported documentation into `dist/docs/`:

```bash
npm run build
.build/docs-env/bin/python .docs-kit/docsite.py publish --project . --out _docs
cp -r _docs/. dist/docs/
npx astro preview        # http://localhost:4321/vial-sort/ and /vial-sort/docs/
```

`publish` refuses an output folder that exists; delete `_docs/` first. On Windows, with the dev server running, `publish` failed to move its bundle into a folder inside the repository ("Access is denied", 2026-11-28); writing to a folder outside the repository worked. The cause was not established.

## Project choices

- The documentation is public at `/vial-sort/docs/`, all of it, by the owner's decision of 2026-11-28.
- `reference_listing` is on: every tracked Markdown file under `docs/` becomes a public page. A file that must stay private does not go under `docs/` without a `private_prefixes` entry in `docs/site/site.toml`.
- Commits use the author's configured Git identity and carry no AI-attribution trailer.
